# 虚拟文件系统设计

## 模块职责

VFS 负责路径解析、目录项、打开文件和挂载路由，使进程访问文件时不依赖后端格式。inode 表示文件对象及操作，dentry 关联名称与父目录，打开的 File 保存访问状态与偏移。任务的描述符表持有文件引用，cwd 提供相对路径基点。

后端通过操作接口实现查找、读写、创建和删除；文件描述符系统调用负责用户缓冲区复制。设备注册与 devfs 负责把设备暴露为文件，不由 ZFS 自行控制硬件。

## 后端及启动策略

| 组件 | 责任 | 数据寿命 |
| --- | --- | --- |
| tmpfs | 内存中的普通文件与目录 | 重启丢失 |
| ZFS | 块设备上的本项目磁盘格式 | 随磁盘镜像保留 |
| initramfs | 解析 newc 归档，提供初始程序 | 取决于加载镜像 |
| devfs | 将设备注册表映射到 `/dev` | 由运行时设备决定 |
| bootstrap | 选择根后端、填充根目录和建立设备挂载点 | 启动策略 |

MMU 启动时，平台提供块设备后才尝试挂载 ZFS。ZFS 挂载失败返回 tmpfs 状态，之后正常复制 initramfs；缺少块设备会报错，不属于该回退。显式 tmpfs 模式同样将归档复制进 RAM。

ZFS 挂载成功后创建必要目录，将归档中缺失的顶层普通文件暴露为只读内存节点。已有磁盘路径优先，嵌套归档路径跳过。这是初始程序补充机制，不是持久复制或完整 overlay。目录枚举合并这些内存子项。根目录初始化完成后，独立 devfs 挂载到 `/dev`。

## 存储格式与一致性

ZFS v2 使用 4 KiB 块、12 个直接块和 1024 项单级间接块，最大文件 4,243,456 字节。双级和三级间接块字段不代表已经支持相应读写。主机格式化与填充工具需要和内核格式一致，旧镜像不能自动当作 v2 镜像挂载。

block 层执行固定块大小检查、读缓存和写穿更新，并对每个打开句柄的读写加锁。这只保护单次块操作；ZFS 的位图、inode 与目录多步骤更新、VFS 对象生命周期仍缺少完整事务/并发保证。当前没有日志恢复承诺。

## 使用边界

路径长度、描述符数量和用户复制缓冲区受内核限制；调用者必须处理失败与短读写。fork 共享打开文件引用，不能假定子进程得到独立文件偏移。设备节点访问还依赖设备注册成功及对应操作支持。

小核直接创建 tmpfs 与 devfs，复用相同 VFS 抽象，但其 shell 是内核任务，不通过 MMU 用户 syscall 路径。
