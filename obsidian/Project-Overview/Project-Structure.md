# 项目模块与维护边界

## 组织原则

项目按硬件机制、资源管理和服务接口划分模块。阅读时先理解职责与依赖，再到源码定位具体行为；文件位置不是稳定 API，构建图中的模块导入才描述当前边界。

| 领域 | 维护责任 | 主要协作对象 |
| --- | --- | --- |
| 板级适配 | 内存所有权、设备地址、启动形态 | arch、驱动、构建系统 |
| 架构机制 | CSR、SBI、锁、CPU 状态 | 内存、trap、调度 |
| 资源管理 | 页、堆、进程、执行切换 | 页表、syscall、VFS |
| 设备与存储 | 注册、硬件驱动、块缓存 | platform、devfs、ZFS |
| 文件服务 | 路径、挂载、文件与启动填充 | 任务描述符、块设备 |
| 用户运行库与应用 | 入口、有限堆、ABI 封装、命令 | 内核 syscall 与 ELF 约定 |
| 主机工具 | 镜像格式化/填充、FIP 打包、回归驱动 | 构建产物与板级部署 |

## 构建是装配边界

build.zig 选择 board、MMU 策略、根文件系统和产物，生成汇编常量，并组织 Rust 应用与 initramfs。Makefile 提供短命令入口并直接启动交互式 QEMU/GDB。配置来自构建选项，不依赖单独 Kconfig 生成器。

驱动不反向导入 kernel：所需服务通过初始化参数交付。文件系统接收平台提供的块设备，避免根后端策略绑定到 QEMU 探测。公共日志接口在启动时安装，减少公共模块对具体控制台的依赖。
