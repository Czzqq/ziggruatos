# 发展方向与当前边界

## 当前基础

系统已经接入 MMU 进程、基本 SMP、物理页/堆、VFS、ZFS/tmpfs、设备抽象以及 Rust no_std 应用。DuoS 小核另有原生 M-mode 任务执行路径。详细能力及限制以 [当前实现范围](../../docs/IMPLEMENTATION_STATUS.md) 为准，不能把本页计划当作已完成实现。

## 近期设计重点

| 领域 | 设计问题 | 完成判据 |
| --- | --- | --- |
| 并发 | VFS/ZFS 多步状态、驱动全局缓冲与锁边界 | 多 hart 文件操作压力下无资源损坏，错误路径可回收 |
| 内存 | 跨 hart TLB 同步、用户堆增长及资源失败 | 映射更新可见性明确，失败不泄漏，ABI 有实际处理分支 |
| 进程 | 管道、描述符复制和信号基础 | 以端到端进程行为验证，不仅新增调用编号 |
| 用户工具 | 文本工具和 shell 组合能力 | 按依赖先实现必要内核服务，再验收命令行为 |
| 小核 | 装载/重定位契约与硬件稳定性 | Linux 与小核所有权不冲突，真实板级运行可复现 |

## 长期探索

- [REE 应用生态](../../roadmaps/ROADMAP_REE_Apps.md)：文件工具、shell、系统管理与可选网络工具。
- [TEE 概念实验](../../roadmaps/ROADMAP.md)：隔离、切换、信任链与证明的学习顺序。
- [TEE 设计](../../roadmaps/ROADMAP_TEE.md)：可信组件、共享内存与安全边界。
- [虚拟化设计](../../roadmaps/ROADMAP_VM.md)：H 扩展、两阶段翻译和虚拟设备。

这些方向尚未实现完整安全世界或 hypervisor。安全隔离必须来自明确硬件权限和可信计算基；无 MMU 的 M-mode 任务共享内存，不提供任务间隔离。

## 规划维护

每个里程碑需要明确前置能力、职责边界、失败语义与验收方法。时间估算和学习示例不能当作项目事实。完成状态应随实现证据和运行结果更新，并注明验证平台。
