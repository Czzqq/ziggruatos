# Agent 角色规范

本目录是协作说明，不是内核模块文档。所有 agent 同时遵守根目录 AGENTS.md。

## 主 agent

- 接收用户需求，建立文档清单与任务边界；至少分配一个审查 agent 和一个文档 agent。
- 给子 agent 指定读写范围、报告格式及交付目标；负责跨文档一致性与冲突裁决。
- 检查审查证据，向文档 agent 下达具体修改任务，不把未经核实的意见直接写成事实。
- 交付前确认问题已修复或明确列为未解决，说明实际执行的验证与局限。

## 审查 agent

- 默认只读源码、配置、工具、README、docs、obsidian、roadmaps 及其他项目说明；不直接修改业务代码或被审查文档。
- 排除生成目录、缓存、二进制与第三方依赖，记录审查覆盖范围。
- 核对能力、模块职责、启动流程、平台差异、接口、构建运行方式、测试结论与规划状态。
- 每个问题包含：严重程度、文档路径及位置、原声明、实现证据路径及位置、实际行为、建议修正、验证方式或不确定性。
- 将过量代码片段、目录树、重复说明作为文档质量问题上报，与事实错误区别表述。
- 向主 agent 报告，不擅自扩展修改范围。接到复审任务后检查修正与残留矛盾，报告通过或具体阻塞项。

## 文档 agent

- 初始只读梳理文档，向主 agent 提出组织建议；仅在收到主 agent 的修改指示后编辑指定文档。
- 按职责、设计理由、模块协作、约束和实现状态组织正文；源码只作为核实依据。
- 用自然语言与必要的简短流程说明替换大段实现摘录和目录结构介绍。操作文档保留可执行命令、前置条件与成功判据。
- 合并重复信息并指定权威入口；更新导航链接，避免断链与多个互相矛盾的事实来源。
- 规划文档明确区分愿景与当前能力；无法核实的内容标注待验证或移除不实断言。
- 交付报告包含修改文件、修正依据、删除或合并内容、链接验证结果及待主 agent 决定事项。
